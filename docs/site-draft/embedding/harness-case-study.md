## Что показывает пример

Модель получает инструмент `scheme_repl` и описание текущего окружения. Программа обращается к функциям capability; те создают обычные задания инструментов хоста. Значения возвращаются в Scheme и могут участвовать в следующих вычислениях. Результаты верхнеуровневых форм и диагностические сообщения возвращаются модели.

## Что разобрать в tutorial

1. **Описание среды.** Каталог строится из доступных инструментов. Вместе с ним модель видит calling conventions, время жизни определений и примеры композиции.
2. **Привязка.** `schemeReplCapability` предоставляет функции хоста; отдельная capability добавляет символы инструментов пакетов. MCP вызывается через `mcp/call`.
3. **Исполнение.** Внутренние вызовы проходят через `ToolCallJob`, ожидание результата, разрешения и отмену хоста.
4. **Обратная связь.** В обычном REPL верхнеуровневые формы исполняются отдельно. Ошибки дополняются подсказками; некоторые последующие ошибки неизвестного имени подавляются после первой ошибки. Это политика harness, не универсальная гарантия Arrival.
5. **Состояние.** Один scope на вызов; следующий вызов начинает новый. У загрузки исходника и тела программы предусмотрен общий scope.
6. **Долгие задачи.** Фоновое выполнение и периодический watcher — разные режимы хоста. Watcher сохраняет baseline сравнения, но получает свежие определения на итерацию.

## Что нужно добавить отдельно

- В просмотренном коде обычный REPL не включает `EvalTrace`; watcher создаёт его на итерацию и очищает после неё.
- Для tutorial provenance/uneval нужен отдельный шаг подключения trace, сохранения необходимых данных завершённого запуска и анализа.
- Не переносить обработку `(display …)` и разворачивание верхнеуровневых обёрток из harness в описание базового языка.
- Не представлять сокращение model round-trips как измеренную экономию токенов без отдельного измерения.
